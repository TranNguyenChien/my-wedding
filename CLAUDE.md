## What this is

A single wedding invitation site (Next.js 16 App Router, React 19, TypeScript, Tailwind v4). Static content (hero, ceremony details) plus one interactive feature: an RSVP form that writes to a Google Sheet.

Note the `@AGENTS.md` import above: that file is regenerated by `next dev` and carries a load-bearing warning — this Next.js version (16.3.4) has diverged from training data, so read `node_modules/next/dist/docs/` before assuming an API's behavior.

## Commands

- `pnpm dev` — start dev server (Turbopack)
- `pnpm build` / `pnpm start` — production build / serve
- `pnpm lint` — ESLint (flat config, `eslint-config-next`)
- `pnpm exec tsc --noEmit -p tsconfig.json` — typecheck (no separate script in package.json)
- `pnpm exec next typegen` — regenerate `.next/types`; run this (or `rm -rf .next` then typecheck) if `tsc` reports errors pointing at `.next/types/validator.ts` after moving/adding routes — the route type manifest goes stale and produces phantom errors otherwise

No test framework is configured in this repo.

## Architecture

**`src/` layout**: `app/` is routing-only (pages + `route.ts` handlers); everything else lives in `src/components`, `src/services`, `src/types`, `src/constants`, `src/store`. Path alias `@/*` → `src/*` (see `tsconfig.json`).

**RSVP data flow** — client form → own API route → third-party webhook, not a direct third-party call, so the webhook URL stays server-only and the client gets a real success/failure response instead of an opaque `no-cors` one:

1. `src/components/shared/rsvp-form.tsx` — React Hook Form + `zodResolver`, posts to `/api/rsvp` via `src/services/rsvp.ts`.
2. `src/app/api/rsvp/route.ts` — re-validates the same payload with the same Zod schema, then forwards it to `process.env.RSVP_SHEET_WEBHOOK_URL` (a Google Apps Script Web App deployment).
3. `src/types/rsvp.ts` — `rsvp-schema` (Zod) is the single source of truth; `RsvpFormData` is inferred from it (`z.infer`) and used by both the client form and the route handler. Avoid `z.coerce.*` in this schema — its input/output types diverge and break `useForm<RsvpFormData>`'s resolver typing; use RHF's `valueAsNumber`/`valueAsDate` on the field instead.
4. `scripts/google-apps-script.js` — pasted manually into the Google Sheet's Apps Script editor; it is _not_ part of the Next.js app and is excluded from ESLint's scope in `eslint.config.mjs`. Setup steps are in the comment header of that file.

**Content**: `src/constants/site.ts` holds placeholder wedding details (names/date/venue) marked `TODO` — fill in before publishing.

**State**: `src/store/useUiStore.ts` is a scaffolded Zustand store, not yet wired to any component — extend or replace it rather than adding a second store for the same kind of UI state.

**Env**: copy `.env.example` to `.env.local`; only var is `RSVP_SHEET_WEBHOOK_URL`.
